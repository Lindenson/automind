# ADR-021: Deterministic insights and a code-built verdict before the AI writes

**Status**: Accepted · 2026-11-03 (spec 004 US1, US3)

## Decision

A report is built in four steps:
1. Sense-checked facts.
2. `domain/insights.py` finds the meaningful differences with per-attribute thresholds (`config/insights.yaml`) and ranks them by the user's priorities. It expresses consumption in € per year and detects price-versus-running-cost trade-offs with a break-even.
3. `domain/verdict.py` decides the pick or a tie, the reasons, the confidence and what would change the verdict. Code phrases this as the first block, the verdict card, in ru/es/en.
4. The model only explains. `report_check` in `orchestration/guard.py` rejects text that contradicts the blocks: "no data" where data exists, an advantage below the threshold, or a winner in a tie. It allows one regeneration, then removes the offending sentences.

## Consequences

The answer no longer depends on the model's choice of "interesting" facts. 583 L against 580 L is never a win. The same data always gives the same verdict. Thresholds are configuration and need review as the data grows.
