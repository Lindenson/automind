# ADR-026: One API process; source authority by official domain; reporter without tools

**Status**: Accepted · 2026-11-03 (code review of 2026-11-03)

## Decision

1. **One process.** `ChatRunner._tasks` (cancel, busy) and the `EventBus` subscribers (live events) live in process memory. The API runs as one uvicorn process (`--workers 1` in the Dockerfile) and one container. A second worker or replica needs Postgres LISTEN/NOTIFY for events and a DB-held cancel flag first. Starting a turn takes a per-chat advisory lock, and the partial unique index `uq_turns_one_running_per_chat` (migration 0009) forbids a second RUNNING turn, so two tabs or a double click get "busy" even across processes.
2. **MANUFACTURER only for official domains.** A host is a maker's source only if it is in `official_domains` or `manufacturer_sites` (`config/sources.yaml`), or if its registrable name is exactly a brand (`toyota.es`, `bmw.com.sg`) or a brand TLD (`.seat`). A brand inside a longer name is a publication: `toyota-club.net`, `clubseat.es`, `marinmazda.net`, `hondapartsnow.com`. A favourite's `source_type` is used as configured (km77: SPEC_DATABASE, autopista: INSTRUMENTED_TEST). Domain matches respect label boundaries. `scripts/repair-data.sh --sources` re-types the stored evidence and reselects the values.
3. **A user-sent page is chat-scoped.** A price the resolver reads from a URL the user sent is not written to the shared variant catalogue.
4. **The reporter has no tools.** It writes from `comp.facts`, which holds the verdict, the insights, the ownership cost and the block data. The number check allows only the numbers in those facts and blocks, so every number in the text matches what is on screen. The weights, mileage and chat id therefore come from the case, never from the model. Sentences the checks remove are logged (`guard.sentences_removed`), not shown to the user.

## Consequences

Fewer LLM calls per report (no ReAct loop) and one source of truth for numbers. Horizontal scaling is a deliberate later step.
