# ADR-018: Own page store, relevance gate before extraction, deterministic site readers

**Status**: Accepted · 2026-11-02

## Context

Values from the wrong generation or engine reached validation, and LLM extraction of spec tables was costly and
made unit mistakes.

## Decision

Pages are fetched by our fetcher (deny-list, robots incl. Crawl-delay and 401/403 = disallow, redirect re-check,
per-host concurrency) and reduced to main content (trafilatura, tables kept; pypdf for PDFs), stored with an
expiry in `documents`. A pure relevance gate (generation codes, years, engine power, body) rejects other-variant
pages before extraction; only uncertain pages go to a small relevance model. Favourite spec sites are read by one
generic label/value reader configured per site (`config/site_readers.yaml`), enabled per site after the operator
reviewed its terms (`tos_checked`). Plausibility rules and a case-aware validator (market, year) follow.

## Consequences

Rejections carry reasons and are shown in the sources block. Site layout changes make a reader fall back to the LLM
and are counted in `site_reader_stats`. No headless browser: JavaScript-only pages are skipped.
