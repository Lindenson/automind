# ADR-029 — Access before any external demo: anonymous owner per browser, same-site only, daily cap

Status: Accepted (2026-11-04)

## Context

The hub had no access control: any chat id opened any chat (history, case file, panel edits, deletion), the
chat list showed every chat, a page on any site could open the WebSocket and spend the API budget, the research
metrics were public, and nothing bounded the spend across chats. Accounts are out of scope for now.

## Decision

- **Owner per browser.** The first response sets `automind_owner` (random 32 bytes, HttpOnly, SameSite=Lax,
  Secure on https, 400 days). The server stores only its SHA-256 in `chats.owner` (migration 0012). A chat is
  created with its owner; another browser gets 404 `chat_not_found` (REST) or close 4404 (WebSocket), never sees
  it listed and cannot delete it. The page asks `GET /api/v1/session` once before anything else, so its parallel
  first requests share one owner. Chats from before the upgrade (owner NULL) go to the first browser that lists
  chats (or opens one) after it. `OWNER_ISOLATION=false` switches it off.
- **Same site only.** A browser request from another site is refused: the WebSocket handshake (close 4403) and
  every change (POST/PATCH/PUT/DELETE → 403 `origin_refused`). Allowed: the same host, and `ALLOWED_ORIGINS` (the
  Vite dev server by default). No Origin header (curl, tests) is not a browser and passes; it has no cookie of
  anyone else either.
- **Operator endpoints.** `/api/v1/research/metrics` needs `Authorization: Bearer $ADMIN_TOKEN`, or a request from
  this machine when no token is set (through Docker the client is the bridge, so set the token there).
- **Daily cap.** `DAILY_CAP_EUR` (default €5, 0 = none): model and search spend of all chats since midnight
  Europe/Madrid. Research pauses at it with the usual "continue?" question (never cancels) and says what today
  cost; each "continue" allows one more turn allowance past the cap. Answers without research are not stopped.

## Consequences

Not authentication: clearing cookies loses the chats (they stay in the database), and anyone who can reach the
hub can still start chats of their own, bounded by the daily cap. Accounts, rate limits per owner and TLS are the
next steps before a public deployment.
