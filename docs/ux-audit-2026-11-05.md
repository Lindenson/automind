# AutoMind UI audit (frontend/src, branch 010-self-observing-registry, 2026-11-05)

## Summary
1. The pieces exist (intake card, basis badges, case panel, verdict, data panel, provenance badges, "wrong?"), but **what the system understood disappears or is hidden**. The confirmation card is not saved in the conversation, the case panel is closed by default and never signals a change, and the chosen *version* (engine, gearbox, trim) is not shown in the summary, the panel or the verdict.
2. **Correcting the car is expensive.** Car rows in the case panel are read-only (they show "to confirm" or "unknown model" with no action), the intake card can only edit fields that come with chips, and a report has no "not this car/version" action anywhere.
3. **Data-quality signals are weak where users look.** In light mode the provenance and basis badges are ~1.5:1 contrast. Confidence is a coloured dot only. Reasons sit in `title` tooltips, which touch and keyboard users cannot open. When a long report arrives, the view auto-scrolls to the *bottom* (sources), not to the verdict.
4. **Long research and failure states are thin.** The car × area grid *replaces* the stage timeline: it has glyphs with no legend and no elapsed time, and its columns are cut at 390 px. Reconnecting shows only a red dot on phones. Errors and limits offer no next action.
5. **General quality is decent, with gaps.** Dark mode at 1280/390 is clean and touch targets are mostly 36–44 px. But the UI switches to RU/ES while about 50 strings stay English, which contradicts "UI is English per vision" and gives mixed screens. axe found 1 critical and 3 serious issues. Mock mode cannot show the intake, case, progress or verdict flows.

## Findings, ranked by impact on "loses the dialogue / wrong model or version / doubtful data"

### F1. The agreed car version leaves no trace after confirmation, and the version is missing from every "what I understood" surface (High)
- **What:**
  - The intake or confirm card lives outside the transcript (`App.tsx:165-169`).
  - `answerConfirm` and `editIntake` set `confirm: null` and add no message (`store/chat.ts:271-305`), so once the user taps "Yes, research these" the card vanishes for good. Nothing in the chat says what was agreed.
  - The surfaces that remain show only the model and generation, not the version:
    - CaseSummary chips show "VW Golf GTI Mk8 · used ~2021" (`blocks/CaseSummary.tsx:21-31`).
    - The case panel shows "VW Golf GTI Mk8 (2020–)" (`CasePanel/CasePanel.tsx:177-195`).
    - The verdict headline names only the model.
  - The only place with "2.0 TSI DSG" is the spec-table column header, inside a collapsible section (screenshot `09-v2-report-full-1280-dark.png`).
- **Why it hurts:** This is exactly the "picks the wrong version" complaint. The user cannot check, at a glance or later in the thread, which engine, gearbox or trim the numbers belong to. When the version is wrong it looks like "the assistant forgot what I said".
- **Fix:**
  - On confirm or edit, append a compact, read-only "Agreed" entry to `messages`: a role `system` or `intake` entry rendering the card in collapsed form with the final values and their basis.
  - Add the full variant line (engine · gearbox · trim · year) to:
    - CaseSummary
    - the case-panel car row
    - the verdict, as a subtitle under the headline, e.g. "for: Golf GTI Mk8 2.0 TSI DSG vs i30 N 2.0 T-GDi DCT"
  - Needs `variant_label` in `case_file.cars` and `case_summary.cars`. Check the backend payload.
- **Effort:** M

### F2. No cheap way to correct a car or version after the intake card (High)
- **What:**
  - Case-panel car rows show a status badge only ("to confirm", "unknown model", `CasePanel.tsx:30-36, 168-199`). There is no button: no change version, no remove car, no "this is not the car I meant".
  - In the intake card, only fields with `options` get chips (`IntakeCard.tsx:45-57`). Generation, year, mileage and price are read-only and can only be fixed by typing free text.
  - Reports have no per-car "wrong car or version?" action, only per-cell "wrong?" for values.
- **Why it hurts:** Fixing the core error (wrong model or version) costs a free-text turn that the LLM has to reinterpret. That is the same path that misunderstood the user in the first place.
- **Fix:**
  - Add a "Change" action per car in the case panel and in the spec-table column header. It should open the same option chips the intake card uses: generation, engine, gearbox, trim, plus "Not this car" and "Remove".
  - Send it as `intake_edit`/PATCH, a structured edit applied by code rather than by the LLM.
  - For `PROPOSED` and `UNKNOWN_MODEL`, make the badge itself a button.
  - In the intake card, give every field a small "edit" affordance: an inline text input for fields without options.
- **Effort:** M–L (needs a backend endpoint for car edits outside an open confirm request)

### F3. The case panel is hidden by default and silent about changes (High)
- **What:**
  - `useCasePanel` starts with `open: false` (`store/case.ts:102-105`).
  - The "Your case" header button gives no badge or count when a `case_file` with `changes` arrives (`Header.tsx:76-93`).
  - "Last changes" is buried at the bottom of the panel (`CasePanel.tsx:405-413`).
  - At 390 px the panel is a modal sheet you must open on purpose.
- **Why it hurts:** The case file is the main defence against "loses the dialogue", but most users never see it. Silent updates, such as an inferred persona or an assumed 12,000 km, are invisible until a report built on them disagrees with the user.
- **Fix:**
  - On ≥1280 px, open the sidebar automatically on the first `case_file`.
  - Add a dot or count badge on "Your case" when `changes` arrive since the panel was last viewed.
  - Render a one-line inline note in the transcript for each change set, e.g. "Noted: budget €40,000 · usage mountains (you said) · 12,000 km/yr (assumed) — Edit". Tapping "Edit" opens the panel at that field.
- **Effort:** S (badge and auto-open), M (inline change notes)

### F4. A finished long report scrolls to its end, and "What I understood" sits below the verdict (High)
- **What:**
  - `App.tsx:114-118` scrolls to `scrollHeight` whenever `messages.length` changes, so a report arrives and the user lands on the Sources list or the rating row. See `03-mock-report-viewport-390-dark.png` (sources) and `08-v2-report-viewport-*` (verdict scrolled off).
  - `Message.tsx:66-68` puts the verdict first, then the markdown text, then `case_summary` ("What I understood"), then the data panel.
- **Why it hurts:** The user's first view of the answer is footnotes. The check "did it understand me?" comes *after* the conclusion, so a wrong assumption is noticed only after reading a confident verdict.
- **Fix:**
  - When an `assistant_message` with blocks arrives, `scrollIntoView({block:"start"})` the message's first element instead of scrolling to the bottom.
  - Render `case_summary` as a slim "Based on: …" strip *above* the verdict, or as the verdict's first line, with an "Edit" link that opens the case panel.
- **Effort:** S

### F5. Data-quality signals are low contrast in light mode, colour-only or tooltip-only (High)
- **What:**
  - Hard-coded Tailwind -300/-400 colours ignore the light theme:
    - basis badges: `IntakeCard.tsx:9-14`, `CasePanel.tsx:473-477` (`text-emerald-300`, `text-sky-300`, `text-amber-300`)
    - provenance badges: `badges.tsx:12-43` (`text-sky-400`, `text-indigo-300`, …)
  - On white these are about 1.5–2:1 contrast. "you said", "assumed", "CLAIM" and "SIMULATED" are barely readable (`05-intake-card-1280-light.png`, `09-v2-report-full-1280-light.png`).
  - `ConfidenceDot` (`badges.tsx:70-86`) is a 2 px coloured dot with no text or legend. Its `aria-label` sits on a role-less span, so screen readers ignore it (axe `aria-prohibited-attr`, 5 nodes).
  - Several reasons exist only in `title`, which is unreadable on touch and with the keyboard:
    - data-panel status reasons, `DataPanel.tsx:64`
    - intake evidence ("what you said"), `IntakeCard.tsx:20, 37-40`
    - verdict `confidence_reason` on the pill, `Verdict.tsx:20-25`
    - progress cell states, `ProgressGrid.tsx:49`
    - break-even inputs, `Verdict.tsx:91`
  - The sources button is just "🔗 1" with no accessible name (`badges.tsx:199-212`).
- **Why it hurts:** "Doubtful data" partly comes from the user not being able to tell measured from claimed from simulated from assumed. The UI already has this information but makes it hard to see.
- **Fix:**
  - Move badge colours to theme tokens: add `--prov-*`/`--basis-*` variables to `index.css` with light variants (e.g. emerald-700, sky-700, amber-700 on light).
  - Show confidence as text ("high / med / low") or as a dot plus a letter with `role="img"`.
  - Add a single legend line above the spec table: "Claim · Measured · Simulated · Assumption · ●=confidence".
  - Replace `title` reasons with tap-to-expand or a visible second line (the evidence already fits, as the case panel shows).
  - Give the sources button `aria-label="Sources for <row> (<n>)"`.
- **Effort:** S (colours, labels), M (tap-to-expand)

### F6. The "wrong?" control is hard to see and its result is detached from the value (Medium-High)
- **What:**
  - It is an 11 px muted text button repeated in every cell (`ChallengeButton.tsx`, `SpecTable.tsx:107`).
  - It always sends the fixed text `"this is wrong"` (`store/chat.ts:313-319`), with no way to say *why* (wrong version, wrong unit, outdated).
  - After a click it shows "checking…" until reload (no reset, `ChallengeButton.tsx:9,17`).
  - The result is appended as a new bubble at the bottom using the raw key: "Re-checked **zero 100**: corrected: 5.4 s → 5.9 s" (`store/chat.ts:166-186`, `10-error-limit-reconnecting-390-dark.png`). The table cell still shows the old value.
  - The aria-label is hard-coded English.
- **Why it hurts:** This is the cheapest path for "this number is doubtful", but users don't find it, can't explain it, and don't see the fix where the number lives.
- **Fix:**
  - On click, open a two-to-three-option mini menu: "wrong for this version", "outdated", "wrong value", plus optional text. Send it as the `text`.
  - Store `challenge_result` keyed by `car_id|attribute`. Render the outcome inline in the cell (strike-through old value, new value, "re-checked" badge) and use the row label instead of the key.
  - Reset "checking…" when the result arrives.
- **Effort:** M

### F7. Long-research progress: the grid replaces the timeline, has no legend, and is cut on mobile (Medium)
- [x] **Done (fix-ui-audit):** the grid renders inside the StatusTimeline card under the stage rail; the "Resolved: …" line is pinned (also when later steps push it out of the list); elapsed time and Stop sit in the card header; legend kept. The grid scrolls sideways inside its own box with the car column sticky, plus a "Swipe sideways" hint below `sm` (chosen over transposing: one layout at every width).
- **What:**
  - `App.tsx:157-161`: as soon as any `progress` message arrives, `ProgressGrid` replaces `StatusTimeline`. The stage rail, the elapsed seconds and the "Resolved: VW Golf GTI Mk8 (2020–) …" line disappear. That line is the one place the user sees the resolution *during* research.
  - Cells use glyphs `· ⌕ ≡ ✓ ◐ ✕ Ⅱ` with meaning only in `title` (`ProgressGrid.tsx:6-14, 49`).
  - There is no heading, no elapsed time and no estimate.
  - At 390 px the last column ("Value retention") is cut with no scroll hint (`07-progress-grid-390-dark.png`).
  - The Stop button sits detached below, hard-coded "Stop" (`CancelButton.tsx`).
- **Why it hurts:** During 1–3 minute research the user can't tell what is happening, what was resolved, or whether "✕" means failure. This makes things feel "stuck" or "lost".
- **Fix:**
  - Render the grid *inside* the StatusTimeline card under the rail. Keep the elapsed time and the pinned "Resolved:" line.
  - Add a one-line legend (found · reading · partial · not found).
  - On narrow screens transpose the grid: areas as rows, cars as columns. Two cars fit at 390.
  - Put Stop in the card header.
- **Effort:** S–M

### F8. Connection, error, limit and busy states give no next step (Medium)
- [x] **Done (fix-ui-audit):** every error line says what happened, a localized next-step line and one action: generic → Try again (resends the question), overloaded → wait a minute + Try again, limit → Continue with researched data, busy → Stop the research (the running turn stays on screen) or Reload, stopped → Ask again, not sent → Reconnect now, deleted / not found → New chat. The `closed` banner shows at every width with the attempt count and "Retry now" (`Transport.reconnect`); close codes 4403/4404/4410 give a terminal `gone` state ("This chat can't be opened here" + New chat). Classification is by `error.code`, else by the server's wording (`busy:` from api/ws.py, "overloaded or out of quota" from runner.py). All strings in en/ru/es (UI pinned to English).
- **What:**
  - Below 400 px the connection status is a bare coloured dot; its label is hidden (`Header.tsx:49`).
  - "Reconnecting" changes only the composer placeholder to "Connecting to AutoMind…" (`App.tsx:181-183`, `10-*-390-dark.png`). There is no banner and no "your message will be sent / was not sent".
  - Server errors (including limits) render as a red box with text only (`Message.tsx:31-43`). There is no retry, no "ask about cached cars", and `error.code` is ignored except `chat_deleted` (`store/chat.ts:239-267`).
  - If `transport.send` fails, `Composer` has already cleared the typed text (`Composer.tsx:35-40`), so the message is lost.
  - "Stopped.", "Not connected …" and "Loading conversation…" are hard-coded English (`store/chat.ts:198, 381`, `App.tsx:147`).
  - Close codes 4403, 4404 and 4410 set the state to "closed", which reads "Reconnecting…" forever (`transport.ts:96-100`).
- **Why it hurts:** Users read silent failures as "it lost my dialogue".
- **Fix:**
  - Add a slim banner under the header for `closed`, with the attempt count and a "Retry now" button.
  - Have `Composer` clear text only when `onSend` returns true.
  - Map `error.code`: limit → show reset time plus "Answer from cached data"; busy → "A research is running — wait or Stop".
  - Add a distinct terminal state for refused or deleted chats ("This chat can't be opened here — New chat").
- **Effort:** S–M

### F9. i18n is inconsistent: the interface follows the conversation language but about 50 strings are hard-coded English (Medium)
- **What:**
  - `useLang()` returns `manual ?? convoLang ?? "en"` (`i18n/index.ts:18-22`), so a Russian reply switches the UI to Russian.
  - Hard-coded English stays across the UI:
    - case panel: "Who you are", "What matters", "Weights", "Usage", "Money and driving", persona and luggage options, "confirmed" / "to confirm", `CasePanel.tsx:15-36, 130-413`
    - Header: Chats, Your case, New chat, Connected…
    - StatusTimeline stage labels and "AutoMind is working" (`StatusTimeline.tsx:7-24, 77`)
    - SpecTable "unavailable", "cached", "researched" (`SpecTable.tsx:43-49, 74-83`)
    - Sources "references", "Rejected pages", "favourite source"
    - LegacyConfirm "Run research", "Yes, these", "Answer with what you have" (`ConfirmCard.tsx:61, 68, 106, 113`)
    - CaseSummary "What I understood" plus persona names
    - Composer hint, ChatList, CancelButton
  - Screenshot `12-ru-mixed-language-1280.png` shows a half-Russian, half-English screen.
  - The `capitalize` class on section summaries (`Message.tsx:103`) produces "Характеристики И Источники" and "Specifications And Sources".
- **Why it hurts:** It looks unfinished and lowers trust. It also conflicts with the stated vision ("UI is English, replies in user's language") versus spec 004 FR-024, so the product decision is unclear.
- **Fix:**
  - Decide first. If the UI stays English, pin `useLang` to `"en"` and drop the "Auto" switch (S). If it localises, move every literal into `en.ts`/`ru.ts`/`es.ts` (M).
  - Either way, remove `capitalize` and use sentence case from the dictionary.
- **Effort:** S (pin to English) or M (full translation)

- **Effort:** S–M

### F12. Rating is hard to find and gives no anchors (Medium-Low)
- [x] **Done (fix-ui-audit):** the verdict card ends with "Rate this answer ↓", which scrolls to and focuses the rating at the report's end; the scale has "useless … very useful" anchors and `role="group"`; ratings ≤ 2 offer the three complaint reasons. A rated report is remembered in this browser (localStorage), so a reload shows the thanks instead of the scale. Server-side persistence would need `rating` in the history payload.
- **What:**
  - Shown only if the message has a verdict (`Message.tsx:117`), at the very bottom after sources and replies.
  - Bare 1–5 numbers with no scale labels (`RatingControl.tsx:16-29`).
  - The `aria-label` sits on a role-less div.
  - State is local, so after a reload the control reappears unrated.

- **Fix:**
  - Add 👍 / 👎 (or 1–5 with "useless … very useful" anchors) near the verdict.
  - On a low score, show three tap reasons: "wrong car/version", "doubtful numbers", "didn't understand what I want", plus a note. This maps directly onto the spec-010 complaint metrics.
  - Persist "rated" state from history.
- **Effort:** S–M

### F14. Accessibility basics (Medium-Low)
- [x] **Done (fix-ui-audit):** persona select labelled, confidence dot `role="img"`, sources button named, Escape on both dialogs plus focus moved into the dialog, Tab trapped and focus returned on close (`useDialogFocus`); report warnings are `role="note"` (errors stay alerts); visually hidden `h1` once the chat starts; composer inside a `footer` landmark; `text-muted/70` informative text and placeholder raised to `text-muted`; the spec table and grid scroll boxes are focusable regions; empty-state examples use `aria-disabled` so they stay reachable while offline. `scripts/ux-smoke.mjs` (1280/390 × light/dark, intake → progress → report → change → limit → reconnect): **0 critical, 0 serious**; the only remaining moderate is `landmark-unique` when two reports with the same regions are on screen.
- **What (axe, see `ux-shots/run-log.txt`):**
  - **Critical:** the persona `<select>` has no label (`CasePanel.tsx:131`, the Section title is not a label).
  - **Serious:** `aria-label` on role-less spans (ConfidenceDot); contrast 3.0–3.6:1 for the unit hints `text-muted/70 text-[11px]` (`SpecTable.tsx:66-70`) and similar `text-muted/70` uses (composer hint, timeline).
  - **Moderate:** no `h1` once the chat starts; textarea outside a landmark.
- **What (code review):**
  - The CaseSheet and ChatList dialogs have no Escape handling, no focus move into the dialog and no focus return (`CasePanel.tsx:434-465`, `ChatList.tsx:74`).
  - The `role="alert"` on notices makes every warning block interrupt screen readers on each report.
  - The rating group has an `aria-label` but no `role="group"`.
- **What works:** the focus outline is the browser default and visible. The Tab order is logical (`13-keyboard-focus-1280-dark.png`).
- **Fix:**
  - Use `aria-labelledby` from the section title to the select.
  - Add `role="img"` to the dot.
  - Use `text-muted` (not `/70`) for informative text.
  - Add Escape handling, focus trap and focus return to both dialogs.
  - Use `role="note"` for warning notices inside reports.
  - Add a visually hidden `h1`.
  - Keep a branded `:focus-visible` ring (`ring-2 ring-accent`) for consistency.
- **Effort:** S
